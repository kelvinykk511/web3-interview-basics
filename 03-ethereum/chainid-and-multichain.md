# Chain ID 與多鏈充幣（給交易所後端）

## 人話

**Chain ID** = 呢條鏈嘅「身份證號」（Ethereum mainnet=1、Sepolia=11155111、BSC=56…）。  
CEX 常見坑：用戶以為「USDT 就係 USDT」，但其實同幣種可以喺唔同鏈（ERC-20 / TRC-20 / BEP-20）。**地址格式可能一樣、合約地址唔同、chainId 唔同**——記錯鏈就等於錢去咗另一個宇宙，交易所帳本對唔上。

## 面試短答

- 簽名交易要帶 `chainId`（EIP-155）：防止同一筆簽名被重放到另一條鏈
- 充幣入帳必須綁定：**network（chainId）+ 幣種合約地址 + 收款地址（+ memo 若需要）**，缺一唔能當同一資產
- 多鏈架構常見：每條鏈獨立掃塊／獨立確認數參數；ledger 層用內部 assetId 映射「鏈×合約」
- 產品側要明確展示「選鏈」；後端拒絕「鏈上到帳但 chainId／合約唔匹配」嘅假充值

## 常見追問＋答案

Q：點解簽名要寫死 chainId？  
A：冇 EIP-155 時，同一份簽名可能喺另一條 EVM 兼容鏈被重放。帶 chainId 後，簽名只對指定鏈有效。

Q：用戶轉錯鏈點辦？  
A：若收款地址喺目標鏈唔受控／合約唔存在，通常**無法自動找回**。產品要事前強提示；運維有時靠人工跨鏈救援（貴、唔保證），唔係標準流程。

Q：點樣喺後端防「錯鏈入帳」？  
A：掃塊服務只掃自己負責嘅 chainId；入帳校驗 `tx.chainId`／節點所屬網絡 + token contract allowlist；同內部 `assetId` 對齊後先 credit。
