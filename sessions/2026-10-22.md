## 概念 1：L2 出金真實成本 — L1 data fee + blob 費波動

### 人話

喺 L2（Arbitrum、Base/OP）出一筆金，你俾嘅 gas 其實分兩份：L2 執行費（好平）+ 把呢筆交易數據貼返去 L1 嘅費用（L1 data fee）。後者先係大頭，而且跟 L1 blob 市場浮動，同 L2 本身幾忙冇必然關係。

### 面試短答

L2 tx 成本 = L2 execution gas × L2 gas price + L1 data fee。OP Stack（Base/OP）嘅 L1 fee 獨立計，可以用預部署合約 GasPriceOracle（`0x420000000000000000000000000000000000000F`）`getL1Fee(txBytes)` 估，上鏈後 receipt 有 `l1Fee` 欄位；Arbitrum 就將 L1 成本折算成額外 gas 加入 gasUsed，可用 NodeInterface `gasEstimateL1Component` 拆出嚟。EIP-4844 後 L2 主要用 blob 貼數據，blob base fee 有自己一套 1559 式調價，blob 需求一爆（例如 blob 用量長期滿過 target）就會指數式上升。所以 CEX 嘅 fee oracle 要分開追 L2 gas 同 L1 data/blob 兩條，唔可以淨係睇 `eth_gasPrice`。

### 常見追問（連答案）

1. **Q：點解 L2 出金費有時突然貴幾倍但 L2 唔塞？**  
   **A：** 因為 L1 data fee 跟 L1 base fee / blob base fee 走，L1 或 blob 市場貴咗，L2 tx 就貴，同 L2 擠唔擠無關。

2. **Q：`eth_estimateGas` 喺 OP Stack 夠唔夠？**  
   **A：** 唔夠，佢只估 L2 execution gas；要另外加 `getL1Fee`。Arbitrum 嘅 estimateGas 已經包埋 L1 部分（所以 gas limit 數字睇落好大），兩條鏈嘅估法唔同，錢包服務要按鏈寫 adapter。

3. **Q：點樣減 L1 data fee？**  
   **A：** 交易數據越細越平：用 ERC-20 transfer 唔好包多餘 calldata、批量出金（一筆 multicall/批量合約攤分固定開銷）、避免喺 blob 價高峰做非緊急嘅歸集/再平衡（歸集可以排隊等平價時段）。

4. **Q：帳本點記？**  
   **A：** 實際 gas 成本 = L2 部分 + l1Fee（OP）或 gasUsed × effectiveGasPrice（Arbitrum 已含），以 receipt 為準入成本帳，唔好用估算值入帳。

### 小練習

**題：** Base 上出 USDT，估算時只用 `eth_estimateGas × gasPrice` 定咗 gas 預算同用戶手續費，blob 價暴升嗰日熱錢包 ETH 消耗快過預期、用戶費唔夠蓋成本。問題喺邊？點改？

**參考答案：** 漏咗 L1 data fee，而佢正正係跟 blob 市場升嘅大頭。改：(1) 估算 = L2 execution + GasPriceOracle.getL1Fee(簽好嘅 tx bytes)；(2) fee oracle 分開監控 L2 gas 同 L1/blob 價，設上限告警；(3) 熱錢包 ETH gas 水位按「包含 L1 fee 嘅實際成本」計 burn rate；(4) 成本帳用 receipt l1Fee；(5) 非緊急歸集排隊避峰。

## 概念 2：出金手續費定價 + 報價鎖定

### 人話

用戶見到嘅「手續費 1 USDT」係交易所報嘅價，真實鏈上成本每分鐘都變。報價要夠蓋成本又唔好嚇走用戶，仲要處理「報價嗰刻」同「真正廣播嗰刻」之間嘅價差。

### 面試短答

常見三種：固定費（簡單但 gas 爆時虧，平時多收）、動態費（按 fee oracle 實時計 + buffer）、混合（固定費 + 上下限，超出觸發動態或暫停該鏈出金）。用戶提交時生成 fee quote（金額、鏈、幣、過期時間如 30–60 秒），確認時 quote 未過期就鎖價扣費，過期要重新報；之後實際 gas 高過報價係交易所吃，低過係收益——用 fee P&L 按鏈監控。手續費同本金分開記帳，扣費喺凍結時一齊凍結。

### 常見追問（連答案）

1. **Q：用戶提交後排隊咗兩粒鐘先廣播，gas 升咗，點？**  
   **A：** 已鎖 quote 就按 quote 收，差價入交易所 gas 成本；但廣播層可以設單筆 gas 上限，超過就延遲等平價（有 SLA 上限）或升級人工，唔好無限追價。

2. **Q：手續費收咩幣？**  
   **A：** 通常收提幣本幣（USDT 收 USDT），因為用戶未必有 ETH；交易所內部要用本幣收入對沖 gas 幣（ETH/TRX/SOL）支出，即係一個隱性 FX 敞口，要定期換倉同監控。

3. **Q：點防報價被刷？**  
   **A：** quote 綁 userId + 鏈 + 幣 + 金額區間 + 過期時間並簽名/存 DB，一次性使用，確認時校驗；唔可以俾前端自己傳 fee 數字。

4. **Q：同鏈內部轉帳（收款方都係本所用戶）點收？**  
   **A：** 可以走內部劃轉唔上鏈，免費或低費，但要按風控規則決定（地址屬於本所充值地址就內部入帳），帳本記內部轉帳流水，唔產生 gas。

5. **Q：點樣知收費合唔合理？**  
   **A：** 每條鏈計 fee 收入 − 實際 gas 成本（含 L1 data fee、失敗重試、加速替換嘅成本），按日報表；長期正太多代表收貴，負代表要調。

### 小練習

**題：** 某日 ETH 主網 gas 暴升 10 倍，固定費 5 USDT 嘅 ERC-20 出金每筆實際成本 20 USDT，排隊單量激增。作為後端你會點做？

**參考答案：** (1) 即時切動態定價或提高固定費上限，新 quote 反映實價；(2) 已鎖 quote 嘅單照收原價，但廣播層按 gas 上限分批處理，非急單延遲到 gas 回落（SLA 內），大額或 VIP 可優先；(3) 前端提示用戶可改用 L2/TRON 等平啲嘅網絡；(4) 監控 fee P&L 同熱錢包 ETH 水位，觸發 gas 幣補倉；(5) 事後復盤調整固定費上下限同觸發閾值。
