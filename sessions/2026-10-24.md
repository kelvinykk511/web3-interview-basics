## 概念 1：穩定幣黑名單凍結（USDT／USDC）

### 人話

USDT、USDC 係中心化發行方嘅合約，發行方可以將某個地址拉入黑名單。被拉黑嘅地址啲幣仲喺 `balanceOf` 度見到，但轉唔走；Tether 仲可以 `destroyBlackFunds` 直接燒走。對交易所即係：熱錢包／充值地址一被拉黑，錢會卡死；出金打去黑名單地址，會失敗或者打咗出唔返。

### 面試短答

USDC（FiatToken）用 `notBlacklisted` 檢查 `msg.sender`、`from` 同 `to`，所以發送方或收款方喺黑名單都會 revert；USDT 舊合約主要檢查發送方（`isBlackListed[msg.sender]`／`transferFrom` 嘅 `_from`），所以打入黑名單地址可以成功但收咗之後轉唔走。交易所要做三樣：(1) 出金簽名前 `eth_call` `isBlacklisted`／`getBlackListStatus`（加 OFAC／KYT 制裁名單）預檢；(2) 監聽自己地址相關嘅 `AddedBlackList`／`Blacklisted`／`DestroyedBlackFunds` 事件，命中即 P0；(3) 資金分散喺多個地址，唔好一個熱錢包放晒，減少單點被凍嘅損失。

### 常見追問（連答案）

1. **Q：`destroyBlackFunds` 對帳點睇？**  
   **A：** 佢會 emit `DestroyedBlackFunds` 但冇 `Transfer` 事件，靠 Transfer 流水對帳會漏，要用 `balanceOf` 快照對帳先捉到差額，再按事件解釋。

2. **Q：用戶充值地址因為收咗黑錢被拉黑點算？**  
   **A：** 該地址資金標記 `frozen`，唔再歸集；用戶帳戶按風控／法務流程凍結；同發行方／執法溝通解凍。帳本上清楚區分「交易所自有資金被凍」同「用戶資金被凍」，前者係損失撥備，後者要睇法務決定。

3. **Q：點解唔可以淨係靠鏈上 revert 擋？**  
   **A：** USDC revert 都要付 gas、用咗 nonce、出金單變失敗要退款；USDT 根本唔會 revert，錢直接卡喺對方。預檢平過事後處理。

4. **Q：預檢有冇 race？**  
   **A：** 有，簽名到上鏈之間地址可能先被拉黑，所以預檢係減少而唔係消滅；上鏈後仍要睇 receipt status 同事件。

### 小練習

**題：** USDC 出金已經簽咗廣播，receipt `status=0`（revert，原因係收款地址喺黑名單）。點處理？

**參考答案：**  
(1) nonce 已用、gas 已扣，唔使填洞，唔好自動重試（重試只會再 revert）；(2) 出金單標記 `failed`，用戶凍結款退返可用餘額（手續費按政策退／唔退），gas 記成本；(3) 該地址加入內部黑名單／地址簿標記；(4) 根因：預檢冇做或者冇覆蓋 USDC，補上 `isBlacklisted` `eth_call` + 制裁名單篩查；(5) 如果係 USDT 呢種唔 revert 嘅情況，錢已經去咗，只能客服 + 發行方流程，所以預檢更重要。

## 概念 2：鏈升級／硬分叉／停擺 Playbook

### 人話

鏈都會「發版」（硬分叉），舊版本節點喺啟動高度之後會唔認新規則嘅區塊，要麼卡住，要麼跟咗少數嗰條鏈。鏈亦會意外停擺（例如 Solana 歷史上幾次全網停擺要 cluster restart）。CEX 角度就係：要喺對嘅時候暫停充提、換好節點、恢復後補掃同核對在途出金。

### 面試短答

**計劃升級：** 提前升 testnet → mainnet 節點、讀 release notes（新交易類型例如 7702 type-4、gas 規則變化）確認 parser 兼容；啟動高度前後暫停該鏈充提；啟動後用 ≥2 個獨立來源對 head block hash 確認自己跟主鏈；恢復時 scanner 游標由暫停高度往前回退一段補掃（`txHash`+`logIndex` 冪等）；先恢復充值，小額測試出金，再全量開出金。

**意外停擺：** 偵測 block height 唔郁／出塊間隔異常（多個 RPC 交叉驗證）→ 自動暫停出金、充值頁顯示延遲；恢復後逐張用 txhash／signature 查在途出金狀態，唔好盲目重簽重發。

### 常見追問（連答案）

1. **Q：點知自己節點跟錯鏈？**  
   **A：** 同多個獨立 RPC／explorer 比較同一高度嘅 block hash；睇 client version、peer 數、EIP-2124 forkid；hash 唔同即刻切走並暫停該鏈。

2. **Q：有爭議嘅分叉（例如 2016 ETH／ETC）要注意乜？**  
   **A：** 重放攻擊——同一張簽名喺兩條鏈都有效。要等 replay protection（EIP-155 chainId）確認先開充提；分叉幣按快照分配係業務決定；兩條鏈分開記帳。

3. **Q：停擺恢復後，之前廣播咗嘅出金點處理？**  
   **A：** **EVM：** 用 txhash 喺健康節點查，冇上鏈就重發同一張已簽 tx（同 nonce），唔好重新簽一張新嘅防雙出。**Solana：** 睇 blockhash 有冇過 `lastValidBlockHeight`，確認過期且冇上鏈先重簽，或者用 durable nonce。

4. **Q：暫停充值係咪代表用戶唔可以轉入？**  
   **A：** 唔係，鏈上照收，只係交易所延遲入帳；恢復後補掃入帳。所以要喺 UI／公告講清楚，防客訴同防用戶重複轉。

### 小練習

**題：** 以太坊升級當晚，你有一個節點冇升級，而 scanner 剛好掛喺佢度。升級後會見到乜？要點救？

**參考答案：**  
舊客戶端唔認新規則區塊，通常會卡喺分叉高度（PoS 下唔太會有長命少數鏈，但唔可以假設）；scanner 冇新區塊 → 充值延遲但唔會亂入帳；另外經呢個節點廣播嘅出金可能冇傳出去。救法：(1) 監控 head 落後／hash 不一致即告警並切去已升級節點；(2) scanner 游標回退到分叉高度前一段補掃，靠 `txHash`+`logIndex` 冪等；(3) 在途出金逐張用 txhash 喺健康節點查，冇上鏈就重發同一張已簽 tx；(4) 事後：升級 checklist 加「所有節點版本核對」+ 升級窗口自動暫停。
