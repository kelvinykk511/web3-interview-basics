# BTC 粉塵攻擊（dust attack）+ coin selection 策略

## 人話
有人向你成千上萬個充值地址每個打幾百 sat（粉塵）。佢唔係送錢，係想：
1. **追蹤**：你之後如果將呢啲粉塵同其他 UTXO 一齊花（同一筆交易多個 input），鏈分析就知道「呢堆地址屬於同一個主人」（common-input-ownership）。
2. **搞你手續費**：粉塵入咗 UTXO 池，coin selection 用佢反而要多付 input 費，甚至「花佢唔抵」（uneconomical UTXO）。
3. **混入風險資金**：粉塵來自黑名單地址，KYT 一掃，你歸集後個熱錢包都沾上風險標記。

## CEX 角度
CEX 地址本來就係「交易所嘅」，私隱冇散戶咁敏感，但：KYT 污染、記帳噪音（每筆都可能觸發充值紀錄）、手續費浪費，都係實際問題。

## 面試短答
> 我哋設最小入帳金額（例如 BTC 低於某門檻唔入帳、唔通知用戶），低於門檻嘅 UTXO 標 frozen，唔參與 coin selection 同歸集。coin selection 用「有效值」= 面值 − 花呢個 input 嘅手續費，有效值 ≤ 0 嘅 UTXO 直接排除。歸集只喺低費率時段做，而且按 KYT 結果分開處理，唔將高風險 UTXO 同乾淨資金混喺同一筆交易。

## 常見追問（連答案）
**Q1：最小入帳金額點定？**
A：至少要高過「將來花呢條 UTXO 嘅成本」：input 大概 vbytes（P2WPKH 約 68 vB）× 預期歸集費率，再加安全系數；另外要對齊產品層「最小充值額」公告。低於門檻：記錄但唔入帳，可累積到門檻再入帳（同一用戶多筆細額合計）——要寫清楚規則，避免客訴。

**Q2：有效值（effective value）點計？點解重要？**
A：effective_value = value − input_vbytes × 當前費率。費率高時好多細 UTXO 變負數，用佢等於倒貼。coin selection 演算法（Branch and Bound 搵冇找零組合、唔得就 knapsack／最大優先）都應該用 effective value，唔係面值。

**Q3：點樣唔被 KYT 污染？**
A：充值掃描時對每條 UTXO 嘅來源做 KYT；高風險 UTXO 隔離（frozen + 合規審查），唔准同其他 UTXO 一齊做 input。因為 BTC 一筆交易多 input 會令鏈分析將所有 input 歸咗一類，熱錢包被標記之後，下游交易所可能拒收你嘅出金。

**Q4：粉塵 UTXO 就咁永遠放喺度？**
A：可以凍結唔理（成本最低）；或者喺費率極低（例如 1–2 sat/vB）時做專門「乾淨粉塵」合併交易，只合併同風險等級、同用途嘅 UTXO，或者乾脆用佢哋補 CPFP 手續費。決策要有報表：凍結粉塵總額同數量要入每日對帳。

**Q5：同 EVM 嘅「零值轉帳／地址投毒」有咩分別？**
A：EVM 嘅投毒係騙人複製相似地址（防法係地址簿、白名單、顯示完整地址）；BTC 粉塵主要係追蹤同污染 UTXO 池（防法係 coin selection 同凍結）。兩者共同點：**細額、批量、唔應該觸發正常入帳流程**。

## 小練習（題目 + 參考答案）
**題：** 費率 40 sat/vB，你有一條 P2WPKH 粉塵 UTXO 2,000 sat。用佢做 input 抵唔抵？最小入帳門檻你會點建議？

**參考答案：** 花佢成本約 68 vB × 40 = 2,720 sat > 2,000 sat，有效值 = −720 sat，唔抵，coin selection 應排除。門檻至少要 ≥ 平時歸集費率下嘅 input 成本再加安全系數；如果歸集通常揀 ~10 sat/vB 時段（成本約 680 sat），可以將最小入帳設喺幾萬 sat 級（例如 0.0001–0.0005 BTC，按產品同競品定），低於門檻嘅 UTXO 標 frozen 唔入帳。
