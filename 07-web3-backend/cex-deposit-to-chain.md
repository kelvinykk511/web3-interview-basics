# 從 CEX 充值流程看鏈上

## 人話（你已熟的產品）

用戶充幣：鏈上轉到交易所地址 → 等到足夠確認數 → 記帳加餘額。你熟的是帳本、風控、到帳狀態機；缺口通常是：**怎麼可靠地「看見」鏈上那筆轉帳**。

## 面試怎麼答

- 監聽方式：自建節點 / 第三方 RPC 訂閱或輪詢、解析 tx / receipt / logs
- 確認數：不同鏈最終性不同；未最終前只能「待確認」
- 對帳：鏈上 txHash + 金額 + 幣種 + 入帳地址（或 memo/tag）↔ 內部 ledger 流水號
- 失敗模式：重組（reorg）、延遲、重複推送、地址重用、假充值（錯合約／錯 chain id）

## 和小額支付／訂單系統的類比

像支付回調：要驗來源、要冪等、要對帳、要處理延遲與重複通知——只是「回調」來自區塊鏈事件而非 HTTP webhook。
