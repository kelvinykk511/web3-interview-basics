# 空投／分叉幣快照分配：交易所點樣派畀用戶

## 人話
項目方話「某時間點持有 X 幣嘅人可以領 Y 幣」。用戶嘅幣放喺交易所，鏈上持有人係**交易所地址**，唔係用戶。所以交易所要自己決定：支唔支持、點樣喺自己帳本做快照、點樣把收到嘅空投按比例分返畀用戶。

## 面試短答
空投／分叉幣係一次「鏈下快照 + 鏈上領取 + 按比例入帳」：先公告支持規則和快照時間（區塊高度），喺嗰個高度對應時刻把所有用戶可用+凍結餘額做一致性快照（含掛單、理財等子帳戶），鏈上用交易所地址領取空投；收到之後按「用戶快照餘額 / 總快照餘額 × 實收空投」計分配，floor 捨入，餘數入平台帳，用 distribution_id 冪等批量入帳。分叉幣仲要等 replay protection 同鏈穩定先開充提。

## 常見追問（連答案）
**Q1：快照點樣做到一致？用戶一直喺度交易喎。**
A：最穩陣係按區塊高度對應嘅時間點，攞帳本流水重建餘額（as-of query：按流水 sequence/時間 截止 sum），而唔係同時 select 所有用戶 balance 表（會有不一致讀）。或者快照時短暫停該幣充提，交易照常但用流水計 as-of。結果落表存檔，可審計可重算。

**Q2：點解唔係直接按鏈上地址分？**
A：鏈上地址係交易所熱/冷錢包和充值地址，同用戶冇一對一關係（歸集之後更加冇）。用戶真正權益喺內部帳本，所以分配一定按帳本快照。

**Q3：分母用咩？**
A：分母用「實際領到嘅空投總量」對應嘅資格餘額，通常 = 用戶快照總額（排除平台自營帳戶，或者按政策包埋）。注意項目方可能按鏈上地址設上限、或者某啲錢包（冷錢包、合約錢包）領唔到，實收可能少過理論值，要按實收分，唔可以按公告比例先墊。

**Q4：分叉幣（例如硬分叉產生新鏈）額外風險？**
A：重放攻擊（同一張簽名兩條鏈有效）——要先確認有 replay protection，或者先做「拆分交易」（split coins）再動用錢包；新鏈可能算力低易 51%，確認數要高；分叉前後舊鏈幣要暫停充提，避免用戶喺快照附近套利。

**Q5：批量派發點避免重複或漏派？**
A：每個 (distribution_id, user_id) 唯一約束；分配結果先生成明細表、對總數（sum 明細 + 餘數 = 實收），審批後分批入帳，失敗可重跑；入帳流水帶 distribution_id 方便查詢同撤銷。

## 小練習（題目 + 參考答案）
**題目：** 快照時 3 個用戶持有 A 幣：100、200、700（總 1000）。交易所實收空投 B 幣 99.99（項目方原本話 1:0.1 即應有 100）。B decimals = 2。點分？餘數去邊？

**參考答案：**
- 按實收分，用最小單位：99.99 = 9999 單位。
- 用戶1：9999×100/1000 = 999.9 → floor 999（9.99 B）
- 用戶2：9999×200/1000 = 1999.8 → 1999（19.99 B）
- 用戶3：9999×700/1000 = 6999.3 → 6999（69.99 B）
- 合計 9997，餘 2 單位（0.02 B）入平台 dust 帳戶並記錄。
- 少收嘅 0.01 B（100 vs 99.99）唔好墊付，公告寫明「按實收比例分配」；同時查明少收原因（某地址領唔到、項目方扣費）。
