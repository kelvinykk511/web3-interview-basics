# 地址投毒／零額 Transfer（CEX 充值掃描）

## 人話（從你熟的 CEX）

詐騙者對你熱錢包／用戶充值地址發一筆 **0 額或極小額** `Transfer`，`from`／`to` 造到**看起來好似你常用地址**（只改中間幾位）。用戶／運營喺區塊鏈瀏覽器「最近互動」複製錯地址，之後提現去咗假地址。

對 CEX 掃鏈工程：呢啲垃圾 log **會打中你嘅 `eth_getLogs` filter**（`to=充值地址`）。若入帳邏輯太天真（見 Transfer 就加餘額、或 UI 展示「最近轉入來源」唔校驗），會污染對帳、客服工具，甚至誤導人工打款。

類比：支付回調洪水 + 釣魚相似商戶號——要過濾、要冪等、要人工確認時用完整校驗，唔好靠「睇落好熟」。

## 面試短答

- **投毒特徵**：`value=0` 或 dust；地址視覺相似（前綴＋後綴相同）；常伴隨假 token 合約（同名 USDT）。
- **掃描器**：入帳條件唔可以只係「有 Transfer 且 to∈充值集」。要：`contract ∈ 白名單`、`value > 0`（或 ≥ 幣種最小入帳）、正確 `chainId`、確認數、冪等鍵 `txHash+logIndex`。
- **零額**：多數 CEX **唔入帳**；可記「觀察／風控」但唔加可用餘額。Dust 可設最低入帳門檻，低於門檻歸集策略另議。
- **人工／客服工具**：展示地址用**完整 checksum** 或強制比對，禁止「縮寫中間 `...`」做唯一依據；熱錢包出金地址來自白名單／用戶綁定表，唔從「最近 log 嘅 from」自動填。
- **同假幣**：同名 symbol 但合約地址唔喺上幣表 → 當噪音或風險告警，**絕不**當正式充值。

## 常見追問（連答案）

**Q：0 額 Transfer 點解能上鏈？唔係浪費 gas 咩？**  
A：攻擊者付 gas 買「瀏覽器歷史污染」。對合約嚟講 `Transfer(from,to,0)` 通常合法。CEX 要喺**業務層**丟棄，唔好假設鏈會幫你擋。

**Q：只 filter `topics` 含 Transfer + to=我哋地址，夠唔夠？**  
A：夠做「候選」，唔夠做「入帳」。仲要白名單合約、金額門檻、確認數、（可選）`from` 風控。多用戶 HD 充值地址要用 indexed `to` 高效濾，但解碼後仍走同一套校驗。

**Q：會唔會同 fee-on-transfer／真實小額充值撞車？**  
A：會。門檻要按幣種配置；FoT 應用 `balanceOf` 增量核對實收（你溫過非標準 ERC-20）。投毒多係 **正好 0** 或假合約；真實小額係白名單合約 + 正數 value。兩者分開處理。

**Q：出金側點防用戶「複製錯相似地址」？**  
A：產品：首次提現地址白名單、小額試提、校驗和／memo、顯示完整地址同風險提示。後端：唔提供「從最近入賬 from 一鍵提現」。風控：新地址大額延遲／人工。掃描器本身擋唔到用戶喺瀏覽器複製錯，但唔好成為錯誤來源。

## 小練習

**題：** 掃鏈見到白名單 USDT 合約、`to=用戶充值地址`、`value=0` 嘅 Transfer；同時另一筆假「USDT」合約、`value=1000000`（6 decimals 顯示像 1 USDT）打入同一地址。系統應點處理？客服問「點解瀏覽器見到入帳我哋無入」點答？

**參考答案：**  
1. 零額白名單 Transfer：標記噪音／投毒觀察，**不加餘額**、唔發「充值成功」。  
2. 假合約：合約唔喺上幣表 → 拒絕入帳；可選告警「同名代幣」。用戶鏈上「見到」嘅係垃圾 token，唔係你們託管資產。  
3. 客服話術：只認官方合約地址列表；瀏覽器「Token 轉帳」唔等於交易所入帳；請用戶核對合約地址。內部工單附 `chainId`、真實／假 contract、txHash、logIndex，方便客服截圖對照。
